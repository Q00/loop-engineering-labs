# 루프 실습 4.1: 루프 위에 그래프를 얹는다 (13분)

당신은 이 실습을 진행하는 Claude Code다. 수강생과 **대화하며** 아래 STEP을 순서대로 진행한다.
4강까지는 루프였다. 한 가지 일을 반복해 깎았다. 오늘은 **책임이 다른 일을 노드로 나누고, 그 안에 루프를 넣는다.**

## 진행 규칙 (반드시 지킬 것)

- **STEP 하나가 끝날 때마다 멈추고** 수강생 확인을 받은 뒤 진행한다.
- 판정은 **반드시 `check.py` · `body_guard.py` · `render_check.py` · `make_chart.py --check`의 출력만** 근거로 삼는다.
  "괜찮아 보인다"는 판정이 아니다. 단 마지막 한 번, 사람이 보는 자리는 남겨 둔다.
- **디자인은 서브에이전트(Task)에게 위임한다.** 그게 노드를 나눈다는 말의 실물이다.
- **xelatex을 두 번 돌린다.** 한 번만 돌리면 쪽번호가 `2 / 1`처럼 어긋난다.
- 빌드 도구 확인: `which xelatex` (없으면 STEP 2에서 멈춘다). `render_check.py`는 Pillow가 필요하다.
- 작업 사본 (직접 실행한다):
  ```bash
  mkdir -p loop41-work && cp -R ~/.claude/skills/loop4-1/{GRAPH.md,design_checklist.md,check.py,body_guard.py,render_check.py,make_chart.py,theme.reference.tex,data} loop41-work/ && cp ~/.claude/skills/loop4-1/sample/outline.tex loop41-work/outline.tex && cd loop41-work
  ```

## STEP 0: 통과했는데 아무도 안 읽는다 (2분)

재료는 4강이 만든 발표 슬라이드 소스 `outline.tex`다. 먼저 채점부터 보여 준다.

```bash
python3 check.py outline.tex data
```

**5/5**다. 슬라이드 수도, 결론 슬라이드도, 실측 수치 3종도, 담당자도, 불릿 개수도 전부 규칙대로다.
이제 실제로 어떻게 생겼는지 뽑아 본다. (xelatex 두 번)

```bash
xelatex -interaction=nonstopmode outline.tex >/dev/null 2>&1; xelatex -interaction=nonstopmode outline.tex >/dev/null 2>&1
pdftoppm -png -r 90 -f 4 -l 4 outline.pdf before   # before-4.png, '영향 범위' 슬라이드
```

`before-4.png`를 연다. 4:3, 오른쪽 아래 네비게이션 점, 화면 절반이 빈 여백, 라틴은 세리프고
한글은 고딕이라 한 줄에서 따로 논다. "오류율최고"는 공백이 먹혔다.
**그리고 장애 보고서인데 그래프가 한 장도 없다.** 숫자 세 개가 글줄에 섞여 있을 뿐이다.

멘트: "내용 검문은 통과했습니다. **그런데 이걸 경영진에게 보낼 수 있습니까?**
루프는 자기가 보는 것만 지킵니다. check.py는 글자를 봤지 픽셀을 본 적이 없습니다."

## STEP 1: 그래프를 그린다 (2분)

`GRAPH.md`를 열어 같이 읽는다. 노드 일곱, 되돌아가는 엣지 둘, 갈라짐과 합침 하나씩이다.
어휘 넷(노드·엣지·상태·권한)과 **디자인 노드의 계약 표**를 짚는다.

여기서 반드시 물어본다: **"그냥 '이거 예쁘게 만들어 줘' 한 번 시키면 안 됩니까?"**
답은 GRAPH.md의 그 문단이다. 그렇게 시키면 대개 문장이 매끄러워지고 숫자가 슬쩍 바뀐다.

그리고 오늘의 두 번째 축을 예고한다. **디자인은 한 번에 안 된다.** 그래서 그래프 안에 루프를 넣고,
멈출 조건을 `render_check.py`에 코드로 적어 둔다.

## STEP 2: 차트 노드 + 디자인 노드 (4분)

먼저 **코드 노드**를 돌린다. 판단이 없는 자리다.

```bash
python3 make_chart.py data .
```

그림 3종이 나온다. `kpi.tex`(결론용 수치 카드) · `timeline.tex`(장애 개요용 사건 축) ·
`chart.tex`(영향 범위용 p95/오류율). 전부 데이터에서 계산한다. 값을 지어내지 않는다.

여기서 `design_checklist.md`를 열어 **왜 3종인지**를 짚는다. 하나만 요구하면 한 바퀴에 끝나서
루프가 안 보이고, 여섯 장 전부에 요구하면 '다음 단계' 같은 장에 억지 그림이 들어간다.

그다음 **에이전트 노드**에 위임한다. 프롬프트에 계약을 그대로 넣는다.

- 대상 파일 절대경로와 "beamer 프리앰블을 다시 쓴다"는 범위
- **허용**: 프리앰블 전체 교체, `\input{...}`으로 그림 3종 끼우기, `\vspace` 같은 배치 명령
- **금지**: 원본 본문 줄을 지우거나 고치는 것, **한글이 든 줄을 새로 더하는 것**
- **요구**: 16:9, 네비게이션 심볼 제거, `xeCJK` 한글 폰트 + `CJKspace=true`, 프레임 제목에 위계,
  그리고 그림 3종을 제 장에 넣기: `kpi.tex`는 결론, `timeline.tex`는 장애 개요, `chart.tex`는 영향 범위.
  **그림은 `\noindent\input{...}\par`로 문단을 끊어 넣는다.** `\par`가 없으면 뒤 문장이 그림 옆에 붙는다
- 결과는 `outline.styled.tex`로 저장한다. `pgfplots`를 프리앰블에 넣어야 차트가 컴파일된다.

받으면 빌드한다. **두 번 돌린다.**

```bash
xelatex -interaction=nonstopmode outline.styled.tex > build.log 2>&1; xelatex -interaction=nonstopmode outline.styled.tex > build.log 2>&1; echo "exit=$?"
```

**빌드가 실패하면 그게 되돌아가는 엣지다.** 로그의 마지막 에러 줄만 넘겨 주고 다시 시킨다.
두 번 실패하면 시간을 지키기 위해 안전망으로 간다: `theme.reference.tex`로 프리앰블을 통째로 갈아끼운다.

## STEP 3: 검문 넷 (2분 30초)

빌드가 됐다고 끝이 아니다. 갈라진 검문을 **넷 다** 돌린다.

```bash
python3 check.py outline.styled.tex data
python3 body_guard.py outline.tex outline.styled.tex
python3 render_check.py outline.styled.pdf outline.styled.tex
python3 make_chart.py --check data .
```

- `check.py` **5/5 유지**: 디자인 후에도 내용이 그대로다.
- `body_guard.py` **권한 경계 지켜짐**: 원본 줄이 순서대로 남아 있고, 더해진 줄은 전부 명령이다.
  더해진 줄을 화면에 보여 준다. `\input{kpi.tex}` 같은 줄만 있고 문장은 없다.
- `render_check.py`: 16:9 · 가장자리 침범 · 빈 페이지 · **그림 3종**. **여기서 미달이면 STEP 2로 되돌아간다.**
  3종을 요구하니 대개 한 바퀴에 안 끝난다. 그게 오늘 보려던 장면이다.
- `make_chart.py --check`: 생성물을 다시 뽑아 문자열로 대조한다. 디자인 노드가 `kpi.tex`를 열어
  숫자를 고쳤다면 여기서 걸린다. **본문만 지킨다고 끝이 아니다. 생성물도 데이터에서만 나와야 한다.**

되돌아가게 되면 라운드를 세며 한 줄로 중계한다. 예: `r2: 빌드 OK, 렌더 미달(그림 1/3)`.

**루프가 도는 것을 보여 주는 것이 이 STEP의 목적이다.** 한 번에 통과하면 오히려 아쉽다.
그때는 그 자리에서 미달을 만들어 본다: 프리앰블의 `aspectratio=169`을 지우고 다시 빌드하면
render_check가 화면비에서 걷어찬다. 되돌린다.

권한 위반도 한 번 만들어 본다. `outline.styled.tex`의 `2500ms`를 `약 2.5초`로 바꾸면
check.py는 3번 규칙에서, body_guard는 바뀐 줄을 그대로 찍어서 잡는다. 되돌린다.

## STEP 3.5: 검문에 판별력이 있는가 (1분)

`render_check.py`의 잉크 항목 기준이 왜 1%인지 짚는다. 처음에는 "여백이 많은 슬라이드"를
잡으려고 2.5%로 뒀는데, before와 after를 실제로 재 보니 **1.5% 대 1.8%**였다. 거의 안 갈라진다.

```bash
python3 render_check.py outline.pdf outline.tex        # before: 미달
python3 render_check.py outline.styled.pdf outline.styled.tex   # after: 통과
```

멘트: "검문을 새로 만들면 **두 산출물에 돌려서 갈라지는지** 봐야 합니다.
안 갈라지는 검문을 게이트에 걸면, 통과 여부가 우연이 됩니다. 저는 그래서 그 항목을
'페이지가 통째로 비었는가'로 낮췄습니다. 남은 셋은 실제로 갈라집니다."

## STEP 4: before / after (1분 30초)

```bash
pdftoppm -png -r 90 -f 4 -l 4 outline.styled.pdf after   # after-4.png
```

`before-4.png`와 `after-4.png`를 나란히 연다. 같은 문장, 같은 숫자다.
바뀐 것은 프리앰블과 `\input` 한 줄뿐이다.

칠판 정리 4줄:

1. **노드를 나눌 근거는 하나다: 책임·권한·검증 방법이 실제로 다른가.**
   내용은 데이터와 대조하고, 디자인은 픽셀을 본다.
2. **권한은 '하지 마라'가 아니라 '무엇은 되고 무엇은 안 되는가'다.**
   그림은 넣어도 되고 문장은 못 쓴다. `body_guard.py`가 그 표를 그대로 검사한다.
3. **그래프 안에 루프가 있다.** 디자인은 한 번에 안 되니 되돌아가는 엣지를 두고,
   멈출 조건을 코드로 준다. 조건이 없으면 그건 루프가 아니라 무한 반복이다.
4. **대부분의 일은 그래프가 필요 없다.** graph engineering은 2026년 7월에 붙은 새 어휘지
   새 기능이 아니다. 한 가지 일에 검증자 하나면 그건 루프다.

마지막 질문: "여러분 일 중에 **검증 방법이 서로 다른 두 단계**가 붙어 있는 것은 무엇인가요?
거기가 노드를 나눌 자리입니다." 답을 받고 닫는다.
