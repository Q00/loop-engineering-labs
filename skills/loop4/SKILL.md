# 루프 실습 4: 어제 한 일에서 내일 쓸 스킬을 캔다 (18분)

당신은 이 실습을 진행하는 Claude Code다. 수강생과 **대화하며** 아래 STEP을 순서대로 진행한다.

오늘 재현하는 것은 microsoft/SkillOpt의 **SkillOpt-Sleep**이다. 공식 설명은
`harvest → mine → replay → consolidate behind a held-out validation gate`,
즉 네 단계에 held-out 게이트가 걸린 구조다. 재료는 `~/.claude/projects`의 Claude Code 기록이고,
채택은 별개다: 라이브 파일은 **명시적 adoption이나 `--auto-adopt`를 줄 때만** 바뀐다.
오늘은 같은 재료(2강에서 본 그 세션 로그)로 이 흐름을 작게 돌리고, 마지막에 채택을 사람이 한다.

**3강과 무엇이 다른가.** 3강 GEPA는 *방금 한 실행 하나*를 반성해서 *지금 쓰는 지시서*를 고쳤다.
오늘은 *과거 기록 더미*에서 반복 과업을 캐내고, 결과를 *한 번도 본 적 없는 장애*로 검증한다.
재료도 시점도 게이트도 다르다. 담당자만 사람에서 에이전트로 바뀐 게 아니다.

## 진행 규칙 (반드시 지킬 것)

- STEP이 끝날 때마다 멈추고 수강생 확인을 받는다. 단 **STEP 3(replay+gate)은 멈추지 않고 연속으로 돈다**. 사람이 개입하지 않는 것 자체가 관찰 대상이다.
- **replay는 반드시 서브에이전트(Task)에게 위임한다.** 지시서 전문과 데이터 폴더 절대경로만 주고, check.py·checklist.md의 존재는 알리지 않는다. SkillOpt도 편집을 만드는 optimizer 모델과 과업을 수행하는 에이전트를 나눈다. 다만 **채점표를 숨기는 것은 오늘 실습의 장치**다. 채점 규칙을 아는 세션이 슬라이드까지 쓰면 "지시서만큼만"이 무너지기 때문이다.
- 채점은 **반드시 `python3 check.py <파일> <데이터폴더>`의 출력만** 근거로 삼는다. 감으로 점수를 매기지 않는다.
- **이 실습 자체를 서브에이전트에 위임하지 않는다.** 위임하면 자식의 tool call이 세션 로그에 안 남아 harvest가 자기 활동을 못 본다. 발표자가 직접 진행한다 (새 창에서 시작해도 된다. 기본 harvest가 최근 72시간을 보므로 재료는 이미 쌓여 있다).
- cd가 유지되지 않는 환경이면 명령마다 작업 폴더 절대경로를 붙인다.
- 작업 사본 (직접 실행한다):
  ```bash
  mkdir -p loop4-work && cp -R ~/.claude/skills/loop4/{PROMPT.md,checklist.md,check.py,trace_read.py,sleep_harvest.py,data,heldout} loop4-work/
  cd loop4-work && cp PROMPT.md PROMPT.v1.bak
  ```

## STEP 0: 오늘의 구도 (2분)

칠판에 네 단계를 먼저 적는다: **harvest → mine → replay + gate → adopt**.

한 문장으로 예고한다: "여러분이 오늘 두 시간 동안 한 일이 파일에 남아 있습니다. 거기서 '또 할 일'을 캐내고, 그걸 다시 돌려 보고, **한 번도 안 본 장애로 시험**해서, 통과한 것만 스킬로 채택합니다. 사람이 하는 일은 마지막 채택 하나뿐입니다."

재료를 한 줄씩 소개한다.
- `PROMPT.md`: 발표 슬라이드 지시서 v1. 한 문장뿐이다. 산출물은 LaTeX(beamer) 소스다.
- `checklist.md` / `check.py`: 코드가 판정하는 규칙 5개. 3번(핵심 지표)은 **데이터에서 실측값을 계산해** 대조한다.
- `data/`: 2강부터 함께한 pay-api 장애. 오늘의 train이다.
- `heldout/`: **아직 아무도 안 본** search-api 장애. 게이트가 여기서 채점한다.

## STEP 1: harvest (2분)

2강에서 본 그 세션 로그에서 지난 며칠간 한 일을 캐낸다.
```bash
python3 sleep_harvest.py
```
기본이 **최근 72시간의 세션 전부**다 (실물 `skillopt-sleep`의 `--lookback-hours` 기본값과 같다). 자는 동안 도는 루프는 "지금 이 대화"가 아니라 지난 며칠의 일을 재료로 삼기 때문이다. 그래서 실습을 **새 창에서 시작해도** 어제 다른 창에서 한 일이 그대로 잡힌다.

출력 첫 줄에 세션이 몇 개 모였는지 나온다. 범위를 바꾸려면:
```bash
python3 sleep_harvest.py --lookback-hours 168   # 최근 일주일
python3 sleep_harvest.py --this-session         # 지금 세션만
python3 sleep_harvest.py --all                  # 프로젝트를 가리지 않고
```

짚을 것: "요청 N건 · 위임 N건 · 산출물 편집 N회 · 검증 실행 N회". 이게 harvest다. 실물 `skillopt-sleep`도 정확히 이 파일들(`~/.claude/projects`의 transcript)을 읽는다.

멘트: "이건 만들어 둔 예제가 아닙니다. 방금 우리가 한 일입니다."

## STEP 2: mine (2분)

같은 출력의 아래쪽을 읽는다. **반복해서 손댄 산출물**과 **여러 번 맡긴 과업**이 빈도순으로 나온다.

수강생과 함께 하나를 고른다. 판단 기준은 하나다: **내일도 또 할 일인가.** 실측 사례에서는 "postmortem 작성 지시서로 문서를 만드는 일"이 서브에이전트 위임 3회로 1위였다. 한 번 하고 끝날 일이면 스킬로 만들 이유가 없다.

멘트: "반복이 곧 후보입니다. SkillOpt-Sleep이 recurring task를 mine한다는 게 이 말입니다."

## STEP 3: replay + gate (7분, 멈추지 않는다)

고른 과업을 현재 지시서로 다시 돌리고, **한 번도 안 본 장애로 채점**한다. 라운드마다:

1. `cp PROMPT.md PROMPT.best.bak`로 현재 최고본을 보존한다.
2. **replay(train)**: 서브에이전트에게 PROMPT.md 전문과 `data/` 절대경로만 주고 슬라이드 소스를 받아 `outline_r<r>.tex`로 저장한다.
   위임 문구에 이 두 줄을 반드시 넣는다. 없으면 생성자가 데이터를 훑다가 이상함을 눈치채고 지시서에 없는 검증을 덧붙여, 게이트가 무엇을 잡았는지 흐려진다 (실측 확인).
   - "지시서에 쓰인 표기를 그대로 쓴다."
   - "지시서에 없는 검증·주석·대안 제시를 덧붙이지 않는다. .tex 소스만 출력한다."
3. `python3 check.py outline_r<r>.tex data` 로 채점하고, X 항목의 **힌트를 전부** PROMPT.md에 반영한다 (누적 편집: 한 항목씩 고치면 다른 항목이 깨지며 진동한다).
4. **gate(held-out)**: 고친 지시서로 **한 번 더 replay하되 이번엔 `heldout/`을 준다.** 받은 소스를 `python3 check.py outline_h<r>.tex heldout`로 채점한다.
5. **판정**: held-out 점수가 지금까지의 최고점보다 오르면 "수용"(이 지시서가 새 최고본), 같거나 내리면 `cp PROMPT.best.bak PROMPT.md`로 되돌리고 "기각". 한 줄로 중계한다. 예: `r2: train 5/5, held-out 4/5`.

중계할 때 한 가지를 분명히 한다. **train은 라운드 시작 시점 지시서로, held-out은 힌트를 반영한 지시서로 잰 점수다.** 같은 버전의 두 성적이 아니다. 이걸 안 짚으면 수강생이 "같은 지시서가 5점과 4점"으로 오해한다.

held-out 5/5가 나오면 종료를 선언하고 라운드 표를 보여준다.

train은 5/5인데 held-out이 4/5로 걸리는 라운드가 나오면 반드시 화면에서 짚는다. 빠진 항목은 거의 언제나 규칙 3(핵심 지표)이다. 지시서에 `p95 최고 2500ms`처럼 **값을 박아 넣었기 때문**이다. pay-api의 값은 search-api에서 틀린 값이다.

멘트: "이건 학습이 아니라 암기입니다. 게이트가 없으면 우리는 이걸 5점짜리 지시서로 착각하고 채택했을 겁니다."

**여기서 루프가 스스로 멈춘다.** train이 5/5라 X 항목이 없고, 반영할 힌트가 없으니 지시서가 그대로다. held-out 점수도 그대로라 계속 기각만 반복된다. 이 교착을 푸는 한 수, 즉 **값을 지우고 구하는 방법을 적는 것은 채점기가 알려주지 않는다.** 사람이 넣는다.

수강생에게 이 사실을 그대로 말하고 직접 편집한다: "그 데이터의 `p95_ms` 최댓값을 `p95 최고 Xms` 형식으로 쓴다"처럼. 그리고 다시 라운드를 돈다. 이번엔 두 데이터 모두 5/5가 나온다.

멘트: "자동 루프가 여기까지 데려다줬고, 마지막 한 칸은 사람이 채웠습니다. 게이트는 **무엇이 틀렸는지**는 알려주지만 **어떻게 고칠지**는 알려주지 않습니다. 그래서 다음 STEP의 채택도 사람 몫입니다."

replay 한 번이 40~90초다. 라운드를 넉넉히 돌려도 되지만, 슬롯이 빠듯하면 r1의 값 박기를 발표자가 직접 편집해 2라운드로 묶을 수 있다.

## STEP 4: adopt (4분)

지금까지 고친 것은 작업 사본일 뿐이다. **라이브 파일은 아직 하나도 안 바뀌었다.**

1. v1 원문과 최종본을 나란히 본다: `diff PROMPT.v1.bak PROMPT.md`
2. 수강생에게 묻는다: "이걸 채택할까요?" 동의를 받고 채택 흉내를 낸다 (실제 스킬 폴더는 건드리지 않는다):
   ```bash
   cp PROMPT.md ADOPTED_SKILL.md
   ```
3. 멘트: "SkillOpt-Sleep은 이 단계를 `--auto-adopt` 없이는 절대 자동으로 하지 않습니다. 밤새 혼자 돌아도 **사람이 채택하기 전까지 라이브 파일은 안 바뀝니다.** 1강에서 빨간 사람 표시를 붙여 둔 그 자리입니다."

### 그럼 `--auto-adopt`를 켜도 되나 (1분)

수강생이 반드시 묻는다. 먼저 오해 하나를 푼다.

**auto-adopt는 게이트를 끄는 게 아니다.** 게이트는 그대로 돈다. 꺼지는 것은 **사람의 확인**이다. 1강에서 게이트를 껐을 때 0.554가 0.026으로 무너진 그 실험과는 다른 층의 이야기다. 거기서는 나쁜 편집이 걸러지지 않았고, 여기서는 걸러지되 **아무도 안 보고 반영된다.**

그래서 판단 기준은 하나로 정리된다. **게이트가 못 보는 것을 감당할 수 있는가.** 오늘 우리가 확인했듯 채점기는 규정에 적힌 것만 본다. 규정 밖의 문제는 전부 통과한다(5강에서 이 얘기를 검문기로 다시 한다).

켜도 되는 쪽으로 기우는 조건 셋을 같이 짚는다.
- **되돌리기가 싼가.** 스킬 문서가 git에 있고 diff·롤백이 되면 잘못 들어와도 복구가 몇 초다.
- **영향 범위가 좁은가.** 내 개인 스킬이면 몰라도, 팀이 공유하는 문서면 사람 한 명의 확인이 훨씬 싸다.
- **held-out이 진짜 대표성이 있는가.** 오늘 우리 held-out은 장애 하나뿐이었다. 실무에서 사례 하나로 자동 채택을 켜는 것은 위험하다.

멘트: "제 답은 '개인 스킬은 켜고, 팀 문서는 끈다'입니다. 다만 정답을 드리는 게 아니라 **무엇을 보고 정해야 하는지**를 드리는 겁니다. 게이트가 규정 밖을 못 본다는 사실을 알고 켜는 것과, 모르고 켜는 것은 다릅니다."

### 넘기기 전에 한 가지 (30초)

최종본 `outline_r<r>.tex`를 다시 띄우고 짚는다. **우리는 이 파일을 한 번도 빌드해 본 적이 없다.**
채점기는 소스의 글자를 봤을 뿐이고, 실제로 어떻게 생겼는지는 아무도 안 봤다.
"규정 밖"의 가장 흔한 얼굴이다. 4.1강이 여기서 시작한다.

칠판 정리 4줄:
- **harvest·mine**: 재료는 어제의 기록이다. 반복이 곧 후보다.
- **replay**: 사람이 아니라 서브에이전트가 다시 돌린다. 채점 규칙을 모르는 채로 돌아야 정직한 점수가 나온다.
- **gate**: 한 번도 안 본 과제로 채점해야 암기와 학습이 갈린다. train만 보면 둘을 구분할 수 없다.
- **adopt**: 자동화의 마지막 칸은 비워 둔다. 그 칸을 열지(`--auto-adopt`) 말지는 **게이트가 못 보는 것을 감당할 수 있는가**로 정한다.

덱 핵심 정리의 회색 박스(오늘 줄인 것)를 한 번 짚는다. 실물 SkillOpt은 여기에 편집 예산(한 라운드에 고칠 양 제한), 기각 편집 버퍼(떨어진 편집을 모아 둠), epoch 단위의 느린 갱신을 더해 학습을 안정시킨다. 편집도 자유 수정이 아니라 추가·삭제·교체 세 종류로 제한된다. 오늘은 뼈대만 돌렸다고 정직하게 말한다. "왜 그런 장치가 필요한지는 라운드를 돌려 보셨으니 짐작이 가실 겁니다. 한 번에 다 고치면 무엇이 효과가 있었는지 알 수 없으니까요."

마지막 질문: "집에 가서 여러분 기록에 물어보세요. `sleep_harvest.py --lookback-hours 168`을 돌리면 이번 주에 무엇을 반복했는지 목록이 나옵니다. 1위가 여러분의 첫 스킬 후보입니다." (기억으로 떠올리라고 하지 않는다. 그게 오늘 배운 것이다.)

## 실물 한 번 보여주기 (시간이 남으면, 1분)

"우리가 손으로 한 네 단계가 실제 도구로 있습니다." 화면에 이 정도만 보여준다.
```
pip install skillopt        # skillopt-sleep CLI 포함
skillopt-sleep run --project . --backend mock --lookback-hours 72
```
설치·실행은 강의장에서 하지 않는다 (백엔드 인증·네트워크가 필요하고 시간이 든다).
harvest → mine → replay → consolidate(held-out gate) → adopt가 그대로 있고, `--auto-adopt`를
주지 않으면 파일을 바꾸지 않는다는 점만 짚는다.

## 예상 질문 대응

- "held-out이 왜 필요한가요? train에서 5점이면 좋은 지시서 아닌가요?": "train만 보면 '값을 외운 지시서'와 '방법을 적은 지시서'가 똑같이 5점입니다. 둘을 구분하는 유일한 방법이 안 본 과제로 채점하는 겁니다. 오늘 그 차이를 화면에서 봤습니다."
- "점수 궤적이 화면마다 다른데요?": 정직하게 답한다. "네, 슬라이드 생성은 LLM이라 라운드 수와 중간 점수는 실행마다 다릅니다. 변하지 않는 것은 둘입니다. held-out 최고점보다 오르는 편집만 수용된다는 것, 그리고 채점은 코드라 같은 파일이면 언제나 같은 점수라는 것."
- "왜 '표기 그대로'만 인정하나요?": "규칙이 결정적이려면 대조가 문자열이어야 합니다. 느슨하게 하고 싶으면 채점기를 고치면 됩니다. 채점기도 파일이라, 이 루프의 편집 대상입니다."
- "auto-adopt를 켜면 위험하지 않나요?": "게이트는 그대로 돕니다. 꺼지는 건 사람의 확인이에요. 그래서 질문은 '위험한가'가 아니라 '**게이트가 못 보는 것을 감당할 수 있는가**'입니다. 되돌리기가 싸고 영향 범위가 좁으면 켤 만하고, 팀이 함께 쓰는 문서면 사람 한 명의 확인이 훨씬 쌉니다."
- "check.py만 통과하면 좋은 발표인가요?": "아니요. 5/5는 '규칙 위반 없음'이지 '훌륭한 발표'가 아닙니다. 다만 규칙 위반이 없는 상태에서 사람 검토를 시작하면 사람은 내용에만 집중할 수 있습니다. 5강에서 이 얘기를 검문기로 다시 합니다."
- "harvest가 빈손으로 나옵니다": 최근 72시간 안에 쓴 세션이 없거나, 이 실습을 서브에이전트에 위임한 경우다(자식 기록은 부모 로그에 안 남는다). `--lookback-hours 168`로 기간을 늘리거나 `--all`로 프로젝트 제한을 푼다.
