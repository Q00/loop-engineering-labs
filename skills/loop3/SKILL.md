# 루프 실습 3: 모델은 그대로, 지시서가 학습한다 (17~22분)

실측 기준 2라운드 완주는 20분이다. 15분 슬롯이면 STEP 5의 밸브(2라운드째는 발표자 시연)를 쓴다.
단, 시간에 여유가 있으면 2라운드를 살리는 쪽이 좋다. "또 돌아가네요"가 이 실습의 핵심 장면이다.

당신은 이 실습을 진행하는 Claude Code다. 수강생과 **대화하며** 아래 STEP을 순서대로 진행한다.
오늘의 루프는 GEPA(Genetic-Pareto, arXiv 2507.19457)의 뼈대를 사람 손으로 돌린다:
**실행 → 기록 → 반성(reflection) → 지시서 변이 → 더 나은 것만 생존**.
다만 논문에서 reflection을 쓰는 LLM 자리에, 오늘은 **수강생이** 앉는다.

## 진행 규칙 (반드시 지킬 것)

- **STEP 하나가 끝날 때마다 멈추고** 수강생 확인을 받은 뒤 진행한다.
- 작업은 현재 폴더에 사본을 만들어 진행한다 (직접 실행한다):
  ```bash
  mkdir -p loop3-work && cp -R ~/.claude/skills/loop3/{PROMPT.md,checklist.md,data} loop3-work/ && cd loop3-work
  ```
- **cd가 유지되지 않는 환경이면 이후 모든 명령에 `loop3-work/` 경로를 붙인다.** STEP 2.5의 마커(`--since mark-v1.txt`)와 STEP 4의 diff가 상대경로라 cwd가 풀리면 "파일이 없다"로 즉사한다.
- **이 실습을 서브에이전트에게 위임하지 않는다.** 위임하면 자식의 tool call이 세션 로그에 남지 않아 STEP 2.5가 "(없음)"만 보고한다 (실측 확인).
- postmortem을 쓸 때는 **반드시 PROMPT.md에 적힌 지시만 따른다.** v1 지시서는 일부러 부실하다. 그 부실함이 결과에 그대로 나타나야 실습이 성립한다. 지시에 없는 것을 알아서 잘해주면 안 된다.

## STEP 0: 재료 소개 (1분)

- `data/`: 2강에서 본 그 장애다 (pay-api, 2026-07-12). 2강을 들었다면 "그 데이터 그대로"라고 한 줄로 연결한다.
- `PROMPT.md`: postmortem 지시서 v1. **지시는 딱 한 문장**, 그 아래 공통 규칙 한 줄("지시서가 곧 상한이다")뿐이다. 화면에 그대로 보여주고, 공통 규칙은 앞으로 어떤 버전에서도 지워지지 않는다고 짚는다. 결과가 모델 재량이 아니라 지시서에 고정되는 장치다.
- `checklist.md`: 채점표 5문항. 아직 열지 않는다 (채점 때 연다).

## STEP 1: v1 실행 (2분)

먼저 이 실행 구간만 잘라 볼 마커를 만든다. 2강에서 본 세션 로그는 세션 전체를 누적하므로, 마커가 없으면 앞 강의에서 읽은 기록까지 섞인다.
```bash
touch mark-v1.txt
```
그다음 PROMPT.md의 지시만 따라 postmortem을 쓰고 `out_v1.md`로 저장한 뒤 화면에 보여준다.
("한 단락으로 써라"뿐이므로 시각·설정값·행 번호 인용·담당이 빠진 밋밋한 단락이 나온다.)

## STEP 2: 채점 (수강생과 함께, 3분)

`checklist.md`를 열고 5문항을 하나씩 수강생과 대조한다. 항목마다 out_v1.md에서 해당 부분을 짚으며 O/X를 수강생에게 묻는다. v1은 보통 0~2점이다 (실측 테스트에선 0/5). 합의된 점수를 기록한다.

예상 질문 대응 ("규칙 없이도 모델이 알아서 잘하지 않나요?"): 정직하게 답한다. "맞습니다. 그래서 v1을 '지시서에 적힌 만큼만' 하도록 고정했습니다. 결과 품질이 모델이 아니라 지시서 품질에 좌우되는 실무 상황을 그대로 재현한 겁니다."

## STEP 2.5: 점수 말고 과정을 본다 (1분 30초)

채점은 "무엇이 빠졌나"만 알려준다. **왜 빠졌나**는 2강에서 본 그 tool call 기록에 있다. v1을 쓸 때 무엇을 열었는지 확인한다:
```bash
python3 ~/.claude/skills/loop3/trace_read.py --since mark-v1.txt --touched
```
건드린 파일 목록이 나온다. `data/` 세 파일 중 목록에 **없는** 것이 건너뛴 파일이다 (읽은 것만 찍히므로 부재로 읽는다). `checklist.md`도 같이 뜨는데 방금 채점하려고 우리가 연 것이다. "우리 발자국도 같이 찍힙니다" 한 줄로 넘긴다.

실측 사례: `metrics.jsonl`만 열고 `app.log`·`deploys.log`를 건너뛴 실행에서 out_v1.md가 "배포와 관련이 있을 가능성이 있으며"로 끝났다. 배포 이력을 물리적으로 안 열었으니 v2.3.1을 쓸 수가 없었던 것이다. 특정 파일을 짚어 강조하려면 판정형으로 한 번 더 보여준다 (빨간 글씨가 목록보다 세다):
```bash
python3 ~/.claude/skills/loop3/trace_read.py --since mark-v1.txt --read-check deploys.log
```

`tool call 0개`가 나오면 기록이 없는 게 아니라 **세션 로그를 잘못 골랐거나 마커 경로가 어긋난 것**이다. 출력 첫 줄의 경로가 지금 세션인지 확인하고, 아니면 `--log <경로>`를 붙인다. cd가 풀린 환경이면 마커도 `--since loop3-work/mark-v1.txt`처럼 경로를 붙여야 한다.

멘트: "점수는 '2번 항목 X'라고만 말합니다. 기록은 '배포 이력을 아예 안 열었다'고 말합니다. GEPA가 점수 대신 실행 기록을 읽는 이유가 이겁니다. 무엇이 틀렸는지가 아니라 **왜 틀렸는지**가 여기 있습니다."

세 파일을 다 읽었는데도 점수가 낮게 나왔다면 그대로 짚는다: "읽기는 다 읽었네요. 그럼 문제는 재료가 아니라 지시서입니다. 읽은 것을 쓰라고 안 했으니까요." 어느 쪽이든 다음 STEP의 피드백 근거가 된다.

## STEP 3: 피드백을 지시서에 반영 (3분)

수강생에게 묻는다: "어떤 점이 아쉬웠나요? 말로 해주세요." (예: "언제 시작해서 언제 끝났는지 모르겠다", "원인이 두루뭉술하다", "로그 어디를 봤다는 건지 모르겠다") STEP 2.5에서 본 기록도 근거로 같이 쓴다.

받은 피드백으로 **PROMPT.md를 편집한다**. 그 전에 백업한다. **라운드 번호를 붙인다** (2라운드째에 `PROMPT.v1.bak`을 다시 쓰면 v1 원본이 지워진다):
```bash
cp PROMPT.md PROMPT.v<지금버전>.bak   # 1라운드면 PROMPT.v1.bak, 2라운드면 PROMPT.v2.bak
```
편집 원칙: 수강생 피드백을 지시문으로 번역해 추가한다. checklist를 몰래 베끼지 말고, 수강생이 말한 것만 반영한다 (2~3라운드 돌 여지를 남긴다). PROMPT.md의 공통 규칙 줄은 지우지 않는다.

## STEP 4: diff 관찰 (2분)

```bash
diff PROMPT.v<지금버전>.bak PROMPT.md
```
(cd가 풀리는 환경이면 loop3-work/ 경로를 붙여 실행한다.)
diff를 같이 읽고 두 문장으로 정리:
- "방금 이 diff가 이 시스템의 학습입니다. 가중치는 1비트도 안 바뀌었습니다."
- "방금 여러분이 말로 한 그 피드백을 GEPA 논문은 natural language reflection이라고 부르고, LLM에게 쓰게 합니다. 다음 강의에서 그 자리를 에이전트에게 넘깁니다."

## STEP 5: 재실행과 재채점 (3분)

새 PROMPT.md로 다시 postmortem을 써 `out_v2.md` 저장 → checklist 재채점 → 점수 시각화:
```bash
python3 ~/.claude/skills/loop3/loop_view.py <이전점수> <새점수>
```
5점이 안 되면 STEP 3으로 돌아가 한 라운드 더 돈다 (이게 루프라는 것을 말로 짚는다). 라운드를 더 돌 때는 직전 라운드 점수와 새 점수로 실행한다. 시간이 없으면 2라운드째는 발표자 시연으로 대체해도 된다.

## STEP 6: 마무리 (1분)

칠판 정리 3줄:
1. 오늘 루프의 5단계: 실행(STEP 1) → 채점(STEP 2) → **기록 읽기(STEP 2.5)** → 편집(STEP 3) → 재실행(STEP 5). GEPA가 자동으로 돌리는 루프와 같은 뼈대다. 2강에서 관찰한 tool call 기록이 여기 2.5에서 재료로 들어왔다.
2. 여러분이 한 채점이 프로덕션에서는 **자동 평가**가 되고, 여러분이 한 reflection은 **LLM의 일**이 된다. 사람이 매번 할 수 없으니까.
3. 편집 대상이 파일(지시서·스킬·메모리)이면 diff·리뷰·롤백이 된다. 그래서 프로덕션 self-improvement는 가중치를 그대로 두고 문서를 고친다.

마지막 질문: "여러분 업무에서 PROMPT.md 역할을 할 문서는 무엇인가요?" 답을 받고 마무리한다.
