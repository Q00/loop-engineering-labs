# 오늘 돌릴 그래프

루프는 한 가지 일을 반복해 깎는다. 그래프는 **책임이 다른 일**을 노드로 나누고,
무엇이 무엇 뒤에 올 수 있는지를 엣지로 못 박는다. 그리고 **그래프 안에 루프가 들어간다.**

```
  [0] 재료: outline.tex          내용 5/5로 통과된 보고서. 그런데 못생겼다.
       │  state: { tex, data, round }
       ▼
  [1] 차트 노드  make_chart.py    코드 노드. 데이터에서 그림 3종을 뽑는다. 판단 없음.
       │
       ▼
  ┌──[2] 디자인 노드 ────────┐    에이전트 한 바퀴. 권한: 프리앰블 + 그림 배치
  │      outline.styled.tex  │
  │       ▼                  │
  │  [3] 빌드 (xelatex) ─────┤  실패하면 되돌아간다
  │       ▼ 성공             │
  │  ┌────┴──────────┐       │
  │  ▼               ▼       │
  │ [4a] 내용 검문  [4b] 권한 검문
  │  check.py        body_guard.py
  │  5/5 유지?       지우지 않았나 · 새 문장 안 썼나
  │  └────┬──────────┘       │
  │       ▼                  │
  │  [5] 렌더 검문 render_check.py   16:9 · 넘침 · 빈 페이지 · 그림 3종
  │      + make_chart.py --check    생성물이 손으로 고쳐졌는가
  └───────┴── 미달이면 라운드를 올려 다시 ──┘
          │ 전부 통과
          ▼
  [6] 사람이 본다               예쁜지는 여기서만 판정된다
```

**[2]에서 [5]로 갔다가 되돌아오는 이 고리가 오늘의 핵심이다.** 노드를 나눴다고 끝이 아니다.
디자인은 한 번에 되지 않으므로, 그래프 안에 루프를 넣고 **종료 조건을 코드로** 준다.

## 네 가지 어휘

| | 이 그래프에서 |
|---|---|
| **노드(node)** | 경계가 있는 작업 하나. 코드일 수도(차트·빌드·검문), 에이전트 한 바퀴일 수도(디자인) 있다. |
| **엣지(edge)** | 다음에 올 수 있는 것. 빌드 실패와 렌더 미달은 디자인으로 되돌아가고, 통과는 사람에게 간다. |
| **상태(state)** | 노드 사이를 흐르는 것. 파일 경로(`tex`·`data`·그림 3종)와 라운드 수. |
| **권한(authority)** | 각 노드가 **건드려도 되는 것**의 경계. 디자인 노드는 프리앰블과 그림 배치까지. |

## 디자인 노드의 계약

권한은 "아무것도 하지 마라"가 아니다. **무엇은 되고 무엇은 안 되는가**다.

| 된다 | 안 된다 |
|---|---|
| 프리앰블 전체를 다시 쓴다 | 원본 본문 줄을 지우거나 고친다 |
| `\input{kpi.tex}`처럼 그림을 끼운다 | 새 문장을 쓴다 (한글이 든 줄을 더한다) |
| | 생성된 그림 파일을 손으로 고친다 |
| `\vspace` 같은 배치 명령을 더한다 | 수치 표기를 바꾼다 |

`body_guard.py`가 이 표를 그대로 검사한다. 원본 줄이 순서대로 다 남아 있는지 보고,
더해진 줄에 한글이 있으면 "새 문장을 썼다"로 잡는다.

## 왜 한 노드에 다 맡기지 않는가

"이 보고서 예쁘게 만들어 줘"를 한 번에 시키면 대개 이렇게 된다.
문장이 매끄러워지고, 불릿이 정리되고, **숫자가 슬쩍 바뀐다.**
p95 2500이 2,500이 되고 "약 2.5초"가 된다. 그러면 check.py의 3번 규칙이 깨진다.

내용과 디자인은 **틀리는 방식이 다르다.**
내용은 원본 데이터와 대조해야 잡히고, 디자인은 렌더된 픽셀을 봐야 잡힌다.
검증 방법이 다르면 노드를 나눌 이유가 생긴 것이다. 그게 이 그래프의 근거다.

## 검문에 판별력이 있는지부터 본다

`render_check.py`를 만들 때 잉크 비율로 "여백이 많은 슬라이드"를 잡으려 했다.
before와 after를 실제로 재 보니 **1.5% 대 1.8%**였다. 거의 구분이 안 된다.
그래서 그 항목은 "페이지가 통째로 비었는가"로 낮추고, 판별력이 있는 셋(화면비·넘침·그림)을 남겼다.

검문을 새로 만들면 **두 산출물에 돌려서 갈라지는지 확인해야 한다.**
갈라지지 않는 검문은 통과 여부를 우연으로 만든다.

## 그래도 대부분은 루프면 된다

graph engineering은 2026년 7월에 "loop engineering 위층"으로 불리기 시작한 이름이다.
새 기능이 아니라 새 어휘다. 그리고 정직한 안내문은 이렇게 시작한다: **대부분의 일은
그래프가 필요 없다.** 한 가지 일에 검증자 하나면 그건 루프다.

노드를 나눌 근거는 하나뿐이다. **책임·권한·검증 방법이 실제로 다른가.**
다르지 않은데 나누면, 없던 분산 시스템 문제를 사서 떠안는다.
