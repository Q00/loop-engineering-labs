# postmortem 지시서 v3

data 폴더의 metrics.jsonl, app.log, deploys.log 세 파일을 모두 읽고, 같은 장애를 분석한 postmortem을 유효한 HTML 문서로 작성하라.

HTML에는 다음 다섯 내용을 각각 명시하라.

1. 타임라인: 장애 시작 시각을 분 단위로 `14:20` 전후라고 쓰고, 복구 시각을 `14:52` 롤백 완료 또는 `15:10` 정상화로 쓰라.
2. 근본 원인: `v2.3.1` 배포와 설정값 `db_pool_size`가 `50`에서 `10`으로 바뀐 사실을 함께 쓰라.
3. 영향: metrics.jsonl에서 확인한 수치를 하나 이상 쓰라. `p95 최고 2500ms` 또는 `err rate 최고 9.8%`를 포함하라.
4. 근거: 사실을 뒷받침하는 파일명과 행 번호를 본문에 인용하라. 최소 한 개 이상 `app.log 7행`처럼 쓰고, 가능하면 배포·원인·롤백을 각각 `app.log 3행`, `app.log 7행`, `app.log 17행`으로 인용하라.
5. 재발 방지: 실행 가능한 액션을 최소 2개 작성하고 각 액션에 담당자를 `(담당: ...)` 형식으로 붙이라. 예를 들어 canary 없는 직배포 금지(담당: deployer 팀), 설정값 변경 사전 검증(담당: oncall 팀)처럼 쓰라.

HTML은 제목과 다섯 섹션을 포함해야 하며, 데이터에 없는 사실을 만들지 말라.

(공통 규칙: 이 지시서에 없는 형식·수치·인용은 추가하지 않는다. 지시서가 곧 상한이다.)
